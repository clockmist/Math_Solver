## dpo训练方案介绍
### 1. 相关代码/文件
#### 1.1 merge_model
作用是将qwen-0.5B的基模和方案2训练出来的sft LoRA合并成一个新模型（该模型在测试集上正确率为50%左右）。

#### 1.2 generate_DPO_dataset.py
作用是构造dpo训练时所需要的数据集。train_cot.json中是deepseek v4 flash生成的带有正确的解题过程的数据，用于方案2的sft。但是dpo不仅需要一道题目的正确作答，还需要错误作答，generate_DPO_dataset.py就利用方案2训练出来的模型生成错误答案，存到了dpo_data.json里面。

#### 1.3 train_dpo.py
训练dpo的代码，比较简陋，超参数没怎么调过，目前设定只训练一个epoch。也没有训练中测试。训练结束后会直接将dpo LoRA融进去，保存为一个新的模型。

#### 1.4 evaluate_dpo.py
直接调用train_dpo.py最后保存的模型在一个小的验证集上测试正确率，运行结束后会生成文件记录具体的错误样例。


### 2. 现有进展与问题
现在使用了dpo_data.json中的数据进行dpo训练（大约有300条数据，因为dpo不需要太多数据）,然后训练模型并且测试之后,发现其正确率相比于dpo训练前显著下降,在small_val.json上大约下降了10多个百分点.

原因猜测:
- 训练代码写错了(小概率事件,因为检查过应该没问题)
- 训练集质量太差(大概率), 因为dpo训练需要的是少量但是高质量的数据集, 而且dpo比较擅长的是学习风格,而不是学习对错,所以对训练集的构造要求就更高了.


### 3.后续任务
需要调研针对我们"小学1~6年级的数学应用题"这一任务,应该怎么构造高质量训练集. 现有训练集的问题可能是正确样本和错误样本都是推理,但是推理过程差异较大,导致dpo训练中只学习了推理风格,学不到如何改进错误.(一条思路是构造错误推理时只改动正确推理中的一个式子,比如让这个式子算错结果,写错符号等等.这样子正确推理和错误推理的差异较小,dpo训练时候模型也知道应该去学习什么)

在调研完如何正确有效构建数据集之后,需要重新生成dpo训练数据并训练模型,并加以测试.
